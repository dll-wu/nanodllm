# Packaging

The `nano-dllm` distribution installs the public training, scoring and checkpoint-export commands, plus the CPU-only `paper.companion` module. The wheel places recipes, frozen profiles and reference manifests at the same relative paths as the checkout. Numerical inputs and TeX templates travel inside `paper.companion`. The source distribution also includes documentation, contributor materials, original tiny-text examples and tests.

## Install

Create an isolated environment and install a PyTorch build appropriate to the
platform. Then install the project:

```bash
python -m pip install -e .
```

Development tools:

```bash
python -m pip install -e ".[dev]"
```

The package metadata does not force a private index or a particular CUDA wheel
channel. Follow the official PyTorch selector when a CUDA-specific wheel is
needed.

## Build a release

Choose the commit containing the complete release, including new source files, tests and configuration. From the repository root, build both distributions and check their metadata.

```bash
revision=$(git rev-parse HEAD)
python scripts/build_release_dist.py --revision "$revision" --outdir dist
python -m twine check --strict dist/*
```

The release script exports the selected commit to a temporary directory. The Python build frontend creates the sdist there and builds the wheel from that sdist. Working-tree edits, staged files, untracked profiles and stale build caches stay out of the release. For an offline build, preinstall `build`, `setuptools>=77` and `wheel` and add `--no-isolation`.

The script verifies both archives, stages both copies in the destination and then atomically replaces each release file. If a copy fails, the previous pair stays intact. Use a separate output directory for each release version.

To check an existing pair, pass the directory containing one sdist and one wheel. The default revision is `HEAD`.

```bash
python scripts/check_release_dist.py dist
python scripts/check_release_dist.py dist --revision "$revision"
```

The checker selects public paths from the committed Git tree, requires the exact archive inventories and compares the bytes of each source-derived file with its Git blob, including the wheel’s license copies. It accepts the named files generated by setuptools for the sdist and wheel. Twine checks distribution metadata separately. The sdist must have zero numeric owner IDs and empty owner names on every entry.

An unpacked sdist supports ordinary PEP 517 builds and installs without a Git checkout. Test the installed wheel from another directory to ensure it can locate its paper assets.

## Quality Checks

```bash
ruff check .
ruff format --check .
pytest -q
python scripts/build_release_dist.py
python -m twine check --strict dist/*
```

CI runs these checks on supported Python versions. GPU behavior still requires
an explicit accelerator smoke because hosted CPU CI cannot validate CUDA,
NCCL, BF16, compilation, or memory capacity.

## Dependency Policy

Runtime imports belong in `project.dependencies`; build, test, and lint tools
belong in the `dev` extra. Tokenizer fitting has heavier, pinned standalone
dependencies in the PEP 723 header of
`scripts/train_climbmix_tokenizer.py`, so normal trainer installs do not pull
them in.
